# 要求仕様書

| ID | 受入条件 |
|---|---|
| R1 | API キーなしで正常・劣化モックを実行でき、開発用とホールドアウト用のデータを選べる |
| R2 | 事実、根拠、指示、JSON、保留、模擬機密をルールで判定し、意味的評価を別フィールドに保存する |
| R3 | 429、500、タイムアウトを最大試行回数で打ち切り、異常応答とともに失敗として保存する |
| R4 | モデル・プロンプト・評価器の版とデータセットハッシュを保存し、比較可能な条件に限り品質回帰を判定する |
| R5 | 設定された品質基準と安全性の独立判定に従い終了コードを返す |
| R6 | JSON、CSV、SQLite を通じてリモートで調査・共有できる |
| R7 | Streamlit が記録済みの結果を表示し、モックと実測を切り替える |
| R8 | ロック付き CI で pytest、評価器測定、合否と回帰を検証しレポートを保存する |
| R9 | 実モデルは明示選択時に接続し、認証情報と応答原文を保存しない |

比較ではデータセット、判定ポリシー、評価器、モード、意味判定モデルが一致する必要がある。候補モデルと版、プロンプト版、価格は変更対象にできる。入力テンプレート自体を編集するとデータセットハッシュが変わるため、別条件として扱う。

`--prompt-prefix-file` で共通プロンプトを変更できる。本文のハッシュを記録し、ハッシュが異なる場合は別のプロンプト版を要求する。
