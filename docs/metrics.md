# 評価指標定義書

| 指標 | 定義・分母 |
|---|---|
| Pass Rate | 全チェックに合格した応答数 / 実行対象全件 |
| Accuracy | 正解を返した件数 / 事実性チェック対象件数。対象の終端エラーを分母に含む |
| Faithfulness | 応答内の全行が根拠集合に含まれる件数 / 根拠付きケース件数。対象の終端エラーを分母に含む |
| Hallucination Rate | 未支持行を検出した回答数 / 根拠付きケース件数。実行失敗は Error Rate と評価不能件数に記録 |
| Instruction Following Rate | 指示に合致した件数 / 指示評価対象件数。対象の終端エラーを分母に含む |
| Schema Compliance Rate | 許可されたキーと整数型・値域を満たす件数 / スキーマ対象件数。対象の終端エラーを分母に含む |
| Abstention Accuracy | 正しく回答保留した件数 / 情報不足ケース件数。対象の終端エラーを分母に含む |
| Error Rate | 終端エラー件数 / 実行対象全件 |
| Precision | TP / (TP + FP) |
| Recall | TP / (TP + FN) |
| F1 Score | 2TP / (2TP + FP + FN) |
| False Positive Rate | FP / (FP + TN) |
| False Negative Rate | FN / (FN + TP) |
| P50 Latency / P95 Latency | 実測ミリ秒の nearest-rank 50・95 パーセンタイル。再試行と待機を含む |
| Token Usage | 入出力合計。全件が揃わない場合 null とし、観測分と測定件数を併記 |
| Cost per Successful Task | 全ケースの観測可能な入出力費用合計 / 合格件数。いずれかのケースの費用が不明なら null |

分母ゼロと未測定は JSON の null、CSV では該当セルを空欄とする。正例は人手で定義した未支持の回答。分類不能は混同行列に別集計し、陽性の分類不能は再現率・F1・偽陰性率で FN に加算する。検出器の合否は正常と劣化のラベルを合算して判定する。モックのトークンは空白区切りの疑似値で、障害ケースには記録がない。実モデルでは SDK が返すトークン件数を使う。失敗試行や意味判定の課金は推定対象外で、請求額との照合には提供元の明細が必要。

フォールト注入はモック専用で、3 件とも Pass Rate の失敗に含める。現行データでの正常モデルの上限は 6/9。実モデルではフォールト注入 3 件を対象外とし、呼び出し後に生じた障害は全件集計する。

## 回答品質と実行障害の内訳

通常ケースは `expected_error` が空の行、障害注入ケースはそれ以外の行。通常ケースのうち `error` が空の行を回答取得済みとする。終端エラーは再試行後に残ったエラーを指し、途中の試行だけで発生した障害は件数に加えない。

| 指標 | 分子または件数 | 分母・除外条件 |
|---|---|---|
| `normal_case_count` | 通常ケース数 | 障害注入を除外 |
| `answer_quality_pass_rate` | 通常ケースの回答取得済みかつ `passed` の件数 | 回答取得済みの通常ケース数。終端エラーと障害注入を除外 |
| `answer_quality_failure_count` | 通常ケースの回答取得済みかつ不合格の件数 | 件数。終端エラーと障害注入を除外 |
| `normal_case_success_rate` | 通常ケースの回答取得済みかつ `passed` の件数 | 通常ケース全件。終端エラーを含む |
| `normal_system_error_rate` | 通常ケースの終端エラー件数 | 通常ケース全件 |
| `normal_system_error_count` | 通常ケースの終端エラー件数 | 件数。障害注入を除外 |
| `fault_injection_case_count` | 障害注入ケース数 | 通常ケースを除外 |
| `fault_injection_success_rate` | `error` と `expected_error` が一致した障害注入件数 | 障害注入ケース全件。再試行回数は従来の品質ゲートで別途検証 |
| `normal_error_<code>_count` / `injected_error_<code>_count` | 対象群でコードに一致した終端エラー件数 | 件数。対象コードは `timeout`、`429`、`500`、`provider_error`、`malformed` |

比率の分母が 0 なら JSON と SQLite では `null`、画面では「未測定」となる。件数は対象の観測件数なので 0 を表示する。CSV は従来のケース単位の形式で、`passed`、`error`、`expected_error` から各内訳を再計算できる。画面はケース行から内訳を再計算し、保存済みの内訳と食い違う場合は該当するレポートを除外する。評価器 v2 のように保存済み内訳がないレポートは、再計算値を表示する。品質ゲートと回帰比較の閾値には従来の指標を使用する。評価器 v3 と v2 をまたぐ回帰判定は評価条件の不一致として拒否する。


回答品質合格率は回答取得を条件とする。例えば通常ケース6件中5件が終端エラーで、取得できた1件のみが合格の場合、回答品質合格率は 1/1 で 100%、通常ケース成功率は 1/6 で約 16.7% となる。画面では両方の率と評価対象件数を併記し、終端エラーによる除外を警告する。従来の Hallucination Rate は根拠付きケースの終端エラーを分母に含むため、単独では未支持回答の発生を過小に見せる可能性がある。評価不能件数、Faithfulness と併読する。
