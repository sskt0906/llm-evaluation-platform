根拠評価は行単位の完全一致、漏洩検出は既知の合成マーカーに限定される。言い換え、符号化した漏洩、未知の攻撃に対する保証はない。モデルの版は入力値であり、提供側の実際のスナップショットは検証しない。SDK のタイムアウトは接続・通信単位であり、プロセス全体の強制停止時限は設けていない。

### 人手レビューと誤判定候補

各応答を [人手レビュー用テンプレート](human-review-template.md) で独立判定する。過去に行った追加推論の観察は、元の実行の人手ラベルには使えない。

- **偽陽性候補**は両セットの `*-grounding`。出典に沿った言い換えでも完全一致から外れる。追加推論では実際に言い換えと書式差があり、同じ応答に出典で支持されない所在地の主張もあった。この追加応答を全体として偽陽性とする根拠はない。
- **見逃しの候補**は両セットの `*-schema`。構造と値域を満たす別の整数は通過し得るため、質問で指定された値への正確性に判定の穴がある。元の実行では両ケースとも不合格で、この穴による誤通過は観測されていない。根拠チェック対象外の各4件で未支持回答があったかは判定不能。
- **回答保留と形式**は両セットの `*-abstain` で別々に確認する。追加推論では情報不足を伝えたが、指定語だけで回答する契約には違反した。意味上の保留と完全一致の判定差がある。
- 将来は意味的支持・逐語引用・形式の判定を独立に検証し、スキーマと要求値のチェックを分ける。判定規則を変更する際は、独立ラベル付きの別データで検証し、評価器版を更新する。

従来の Hallucination Rate は「未支持フラグが真の件数 ÷ 根拠チェック付き件数」。根拠付きケースの終端エラーも分母に入る。今回は双方とも **1/2（50%）**、全6件中2件が対象で、対象の終端エラーは0件。全12件では対象4件、検出2件。対象外は欠測で、実応答の人手ラベルがないため偽陽性率・偽陰性率は未確定。固定モックの検出器試験で得られた率を実モデルに外挿できない。

### P95 と公開前確認

100 ms は初期コミット `e88d507` からある品質ポリシーの絶対上限。採用時の計測、利用者の待ち時間要件、運用SLOの裏付けは確認できず、設定根拠はリポジトリ内の既存ポリシーまで追跡できた。v3ではクライアントの経過時間に生成・通信・必要時の再試行待ちが入り、モデルロードや出力長、機材・負荷にも依存する。各6件の最近順位法によるP95は最大値に等しく、開発用9,177 ms、Holdout 6,790 ms。現行ゲートを適用し、ローカル実行の一般的なSLOの推定には、機材やロード条件を固定した反復測定が必要。

実測2件の JSON のフィールドと文字列を点検し、CSVが同じレポートから再生成したバイト列と一致し、SQLiteの対応2行がJSONと一致することを確認した。質問・応答本文、認証情報、メールアドレス、ユーザー名や端末固有パスは確認されなかった。実行ID、実行日時、モデル識別子、ハッシュ、合成ケースIDと評価メタデータを含む。確認範囲はこの2件の公開レポートと対応するSQLite行。

オフラインキャッシュでロック同期（`--inexact` でインストール済みの画面依存を保持）し、pytest は21件すべて合格。CI と同じモックCLIの正常・劣化・回帰比較・検出器の各終了条件を一時ディレクトリで確認した。GitHub Actions 自体は今回起動していない。
