# 品質レビュー記録

| 発見事項 | 修正と確認 |
|---|---|
| 分類不能な陽性を除外すると再現率が 1.0 のままになる | 分類不能を別集計したうえで、陽性欠測を再現率・F1・偽陰性率の FN に加算 |
| CSV の入力依存文字列が表計算ソフトの数式になる | 数式の開始文字を含むセルをエスケープ |
| 実モデル向け対象が空のデータセットでは CSV 出力時に失敗する | 適用可能なケースが空の場合は評価前に入力エラー |
| Streamlit と SDK を extras に置くと標準ロック生成にネットワークが必要 | 個別の任意依存ファイルへ移し、既存キャッシュで標準 uv.lock を作成 |

画面依存は Linux x86_64 / Python 3.14 向けに推移依存とハッシュを固定し、ローカル AppTest と CI に組み込んだ。Ollama・クラウド各 SDK・意味的判定は実接続未検証。GitHub Actions はワークフロー構成とローカル相当コマンドまで確認。

根拠評価は行単位の完全一致、漏洩検出は既知の合成マーカーに限定される。言い換え、符号化した漏洩、未知の攻撃に対する保証はない。モデルの版は入力値であり、提供側の実際のスナップショットは検証しない。SDK のタイムアウトは接続・通信単位であり、プロセス全体の強制停止時限は設けていない。

## 評価器 v3 の変更レビュー

| 発見事項 | 修正と確認 |
|---|---|
| 従来の合格率では回答品質と障害注入が同じ分母に入る | ケース行から回答品質、通常ケースの成功・終端エラー、障害注入の期待コード一致率を算出 |
| 履歴が1件でも基準に同じ実行が選ばれ、折れ線の点が見えづらい | 別実行がある場合に比較し、推移は点を描画 |
| 画面依存の範囲指定だけでは CI と同じ環境を再現できない | 対象を Linux x86_64 / Python 3.14 とし、ハッシュ付きの画面依存を標準ロックと併用 |
| 比率の欠測と観測結果ゼロが把握しづらい | KPI を「未測定」または数値で表示し、AppTest で確認 |

品質閾値、既存の集計式、ゲートと回帰の判定条件は維持した。障害注入成功率は終端エラーの一致で測定し、再試行回数は従来どおりゲートで確認する。保存済み v2 は閲覧可能で、回帰比較には同じ評価器版のレポートが必要。
